Best Models for an Agent Swarm

Note: the rows above are a dated OpenRouter catalog snapshot for comparison and evidence. The `nvidia/nemotron-3-nano-30b-a3b` and `mistralai/mistral-small-creative` rows remain in the snapshot for history only; they are not part of the current runtime defaults.

For an evolutionary chamber (evo-chamber) swarm — where many agents iterate, mutate, evaluate and compete concurrently — the key requirements are high throughput (many parallel calls), low latency (fast iteration cycles), good instruction-following (structured JSON outputs, tool use), and cost efficiency (you'll burn tokens fast at scale).

A practical 3-tier architecture:
🔵 Worker Agents (bulk, parallel, cheap)

These fire constantly — generating mutations, running evaluations, producing candidates. You want maximum t/s and minimum cost per call.

    mistralai/ministral-3b-2512 — $0.10/M, 336 t/s. Best raw speed-per-dollar in the list. Ideal for simple mutation/scoring tasks.

    arcee-ai/trinity-mini — $0.15/M, 217 t/s. Better instruction following than Ministral 3B, still blazing fast.

    deepseek/deepseek-v4-flash — $0.20/M, ~80–150 t/s. Stable low-cost worker model for parallel mutation and evaluation.

    deepseek/deepseek-v3.2 — $0.38/M, ~32 t/s. Higher-reasoning worker when you need a little more depth without leaving the DeepSeek runtime path.

🟠 Orchestrator / Judge Agents (smarter, moderate scale)

These evaluate worker outputs, rank candidates, route tasks, and manage the chamber state. Needs better reasoning than workers but fires less frequently.

    qwen/qwen3-next-80b-a3b-instruct — $1.10/M, 200 t/s. Best reasoning-to-speed ratio in the mid tier — 80B MoE running at 200 t/s is remarkable.

    x-ai/grok-4.3 — preferred Grok judge model for EvoKammer. The older Grok 4 Fast is deprecated and should not be used in runtime pools.

    openai/gpt-oss-120b — $0.19/M, 112 t/s. Underrated: 120B at $0.19/M with solid instruction following, great for scoring pipelines.

🔴 Controller / Synthesizer (one instance, high quality)

The top-level agent synthesising the best candidate, writing final outputs, and steering the swarm direction. Fires rarely, quality matters most.

    google/gemini-2.5-flash — $2.50/M, 86 t/s. Excellent long-context reasoning (1M token window), great for holding swarm state.

    qwen/qwen3-235b-a22b-2507 — $0.46/M, 71 t/s. Massive model at surprisingly low cost — best quality-per-dollar for the controller role if you're cost-constrained.

EvoKammer runtime note:
- The canonical runtime defaults intentionally keep `openai/gpt-oss-120b` for Builder/Grader, `perplexity/sonar` for Archivist, and `x-ai/grok-4.3` for Council and Critic/Judge roles.
- `x-ai/grok-4-fast` is deprecated and intentionally excluded from routine runtime pools.
- `anthropic/claude-sonnet-4.6` is intentionally excluded from routine runtime pools because it is too expensive for the swarm.
- Runtime worker/controller defaults are tuned for swarm throughput and tool stability rather than blindly picking the top-ranked doc entries.
- The current source of truth is `evokammer/core/src/main/kotlin/com/achulkov/evokammer/core/config/ModelSelectionConfig.kt`.
