0. Scope boundary

This document assumes the first dossier has already established the challenge definitions, scoring, public submission landscape, original holdouts, starter agents, EvoMolior role packs and competition roadmap. It adds only the model/runtime engineering layer.

Read this as a decision and experiment manual

The initial dossier remains the source for challenge framing and the two original evaluation tasks. This supplement answers a narrower question: which open weights should be deployed, how should they be changed, and which alternative architectures deserve compute before the Kaggle deadline? [S01][S39]

Source-supported

Current competition requirements, hardware specifications, model cards, public winner designs and reported paper results carry explicit citations.

Inference

Hardware-to-architecture conclusions—such as preferring four independent L4 workers—are marked as engineering inferences rather than organizer guarantees.

Proposal

World-model heads, adapter evolution, task routers and new curricula are research proposals with falsifiable kill gates, not implied leaderboard gains.

1. Decisions before details

The two competitions should share an experiment platform, not a runtime architecture. Their bottlenecks are different enough that forcing one model family or one agent abstraction across both would be a strategic error.

ARC‑AGI‑3 primary
Qwen3.6‑27B‑FP8 + bounded Python REPL

Use image, raw grid and component/delta views; external causal memory; one strict action gateway. This is the strongest public starting point, not a claim that it is the final optimum. [S08][S12]

ARC‑AGI‑3 control
Gemma 4 31B guarded JSON policy

Maintain a simpler direct-policy implementation as the benchmark and operational fallback. Two milestone winners validate the pattern. [S08][S13]

ARC‑AGI‑2 primary
Four-family pass@2 portfolio

Qwen3‑4B TTT, URM/TRM recurrence, executable program synthesis, and 2D refinement—joined by an exact verifier and diversity-aware selector. [S21][S22][S24]

EvoMolior role
Offline research OS, then compiler

Evolve datasets, adapters, harnesses and selectors outside the notebook. Freeze a compact deterministic runtime for Kaggle. Durable evidence and dead-end memory are the useful project primitives. [S38]

2. Hardware is part of the algorithm

Memory capacity determines what can load; memory bandwidth, interconnect and wall-clock determine what can actually reason enough times to score. Treat the accelerator as a changing deployment target, not a stable local workstation.

ARC‑AGI‑2 target
4 × 24GB
NVIDIA L4 workers
  • 300GB/s per card.
  • PCIe Gen4 x16, 64GB/s listed interconnect.
  • 12-hour code-run cap and no internet in the current competition setting.

The four cards provide 96GB aggregate capacity, not a single 96GB address space. Independent workers usually dominate tensor parallelism for small, per-task adaptation workloads. [S07][S09]

ARC‑AGI‑3 current heavy target
96GB
RTX PRO 6000 Blackwell
  • 1597GB/s GDDR7 bandwidth.
  • FP8 and Blackwell FP4 capability.
  • Current starter exposes rtx6000 / g4-standard-48; nine-hour competition runtime.

Use portable FP8 as the default and treat NVFP4 as an optional device-specific branch. [S05][S06][S10]

Portability reference
80–94GB
H100 variants
  • 3.35–3.9TB/s bandwidth.
  • Excellent FP8 support.
  • Substantially more bandwidth than RTX PRO 6000 despite similar or lower capacity.

Do not assume the evaluation pool will never change again. Device-introspective configuration should alter cache and batch settings, not silently switch to an unrelated model. [S11]

The 96GB trap

A model may fit on the RTX PRO 6000 and still decode too slowly. The RTX card has roughly half the memory bandwidth of H100 SXM, so large dense autoregressive decoding can remain bandwidth-bound. Benchmark actions completed per wall-clock minute, not only tokens per second or peak VRAM. [S10][S11]

Wall-clock budgets that force architectural choices

ARC‑AGI‑3 · nine hours

  • Reserve 10–15% for import, model load, engine warm-up and final file writing.
  • Cap per-step generation and Python execution; a single runaway REPL call must not poison the notebook.
  • Use large-model calls on novelty/strategy, deterministic replay on known plans.
  • Track milliseconds per environment action, not only model tokens.

ARC‑AGI‑2 · twelve hours

  • Use a dynamic queue: cheap solvers first, then allocate leftover GPU-minutes to unresolved tasks.
  • Enforce per-task and per-branch deadlines; never let one pathological task starve the submission.
  • Write provisional candidates continuously so a late worker crash does not zero completed work.
  • Prefer independent workers because exact verification combines their outputs cheaply on CPU.

3. Approach atlas: every serious branch, with a kill gate

The priority score is an engineering allocation score—evidence × task fit × hardware fit × marginal diversity—not a predicted Kaggle accuracy. Filter the cards to expose why some fashionable ideas should remain offline research rather than notebook runtime.

ARC‑AGI‑3public96/100

Multimodal code-writing REPL agent

Primary

A VLM interprets rendered frames, raw grids and compact object summaries, writes bounded Python analyses, then emits one legal environment action.

Why it can work
Directly competition-proven with Qwen3.6-27B-FP8; flexible enough to invent game-specific analysis without a huge handcrafted tool ontology.
Failure mode
Generated code can hang, mutate unintended state, or consume tokens. Requires a sandbox, strict action gateway and context eviction.

Baseline / fallback

Feed recent frames and structured memory to a multimodal model and require a schema-valid action or short action queue.

Why it can work
Two top-three milestone systems used this pattern with Gemma-4-31B, legal-action guards, repair and reflection memory.
Failure mode
Less flexible than a REPL when a game demands custom counting, path search or state reconstruction.

Neuro-symbolic causal controller

High-value addition

Classical perception and transition logging maintain objects, state deltas, inventory and hypotheses; the VLM chooses experiments and plans over that substrate.

Why it can work
Reduces repeated no-ops and makes each environment action falsifiable while keeping the model in charge of novel abstractions.
Failure mode
Over-engineered object schemas can erase important visual cues—the milestone winner reported handcrafted tools could hurt.

ARC‑AGI‑3proposal78/100

Model-predictive action search

Moonshot after baseline

Generate a few candidate actions, predict next-state deltas with a learned head or simulator, and execute the candidate with the best expected progress/information gain.

Why it can work
Can trade cheap internal computation for fewer costly environment actions.
Failure mode
A biased learned world model can confidently reject the only useful experiment; tree width also burns the nine-hour runtime.
[S03]
ARC‑AGI‑3inference82/100

Split perception and planning

Benchmark branch

A 4B–15B grounding model extracts components and changes; a 27B–31B planner is invoked only for uncertain or strategic decisions.

Why it can work
Could lower prefill cost and permit richer perception without calling the large model on every trivial step.
Failure mode
Interface errors between perception and planning can be worse than a single end-to-end VLM; two model loads consume memory and startup time.
[S17][S18]
ARC‑AGI‑3proposal84/100

Adaptive cheap/expensive model router

Promising

Use a compact policy for deterministic follow-through and call the large VLM only on novelty, contradiction, low confidence or level transition.

Why it can work
Targets wall-clock efficiency without sacrificing strategic intelligence.
Failure mode
Poor confidence calibration causes either expensive overuse or silent failure on states the cheap model misunderstands.
[S15][S17]
ARC‑AGI‑3proposal73/100

Offline trajectory distillation

Later-stage

Use a strong local teacher to label state changes, efficient actions and plans, then distil into a smaller multimodal policy.

Why it can work
A compact student can afford more decisions and larger rollouts within nine hours.
Failure mode
Public/synthetic teacher trajectories may not cover the hidden mechanics; imitation can preserve the teacher’s blind spots.
[S08][S34]
ARC‑AGI‑3proposal43/100

Online gradient adaptation during play

Usually reject

Update adapters from self-supervised transition prediction while the agent explores a hidden game.

Why it can work
In principle the model can internalize game-specific dynamics.
Failure mode
Sparse, nonstationary labels and a nine-hour cap make catastrophic drift likely. External causal memory is safer and instantly reversible.
[S31][S32]

Multi-agent debate every action

Reject

Several large agents independently analyze each frame, debate and vote before every environment step.

Why it can work
Diversity may help on a handful of pivotal decisions.
Failure mode
The public third-place profile performed best with extra generator/arbiter machinery disabled; debate multiplies latency and correlated speculation.
[S08]
ARC‑AGI‑3baseline55/100

Classical salience/exploration policy

Mandatory fallback

Connected components, rare-color clicks, flood fill, pathfinding, state hashing and reset logic without an LLM.

Why it can work
Fast, deterministic, and useful when model serving fails or the game is mechanically simple.
Failure mode
Cannot infer open-ended goals or unfamiliar causal systems reliably.
[S08]
ARC‑AGI‑2winning97/100

ARC-specialized 4B LLM + test-time training

Primary neural branch

Globally fine-tune Qwen3-4B on executable synthetic tasks, then perform tightly budgeted per-task LoRA/QLoRA adaptation on augmented demonstrations.

Why it can work
Direct 2025 winning-solution lineage; small enough for one L4, leaving three GPUs for uncorrelated branches.
Failure mode
Fits demonstrations easily but may learn the wrong abstraction; must use leave-one-out, equivariance and stability checks.
[S21][S22][S19][S26]
ARC‑AGI‑2winning94/100

2D masked refinement / diffusion

Primary diversity branch

Predict a draft output grid, mask uncertain cells and iteratively repair them using 2D positional structure and perspective-based scoring.

Why it can work
The ARChitects lineage placed second in 2025 and addresses the mismatch between flat token generation and spatial grids.
Failure mode
Training and inference code are more specialized; confidence maps can converge to visually plausible but exact-wrong outputs.
[S21][S22]
ARC‑AGI‑2paper92/100

URM/TRM recurrent refinement

High-upside branch

A tiny or small universal/recurrent transformer repeatedly updates latent and answer states, often with full task-time adaptation.

Why it can work
Tiny models support many seeds and refinements; URM reports 16% ARC-AGI-2 pass@1, while NVARC used TRM components.
Failure mode
Reported scores are sensitive to augmentation and outer-loop training; official analysis warns architecture headlines can hide the real drivers.
[S23][S24][S25]
ARC‑AGI‑2established91/100

Typed DSL / enumerative program synthesis

Mandatory branch

Search composable operations over colors, components, masks, geometry, topology and object relations; execute every candidate exactly.

Why it can work
Gives perfect verification, interpretable failures and strong coverage on structured task families.
Failure mode
A fixed DSL has a hard coverage ceiling and search can explode without neural guidance and structural pruning.
[S04][S27]
ARC‑AGI‑2paper90/100

LLM-proposed Python programs

Competitive branch

Generate transformation functions, execute them against all demonstrations, repair from counterexamples and retain only exact programs.

Why it can work
A general language can express transformations outside a handcrafted DSL; evolutionary/hindsight approaches have strong ARC-AGI-1 evidence.
Failure mode
Many spurious programs interpolate demonstrations; sandboxing and aggressive generalization tests are essential.
[S27][S30]
ARC‑AGI‑2paper88/100

Product of experts across perspectives

Strong selector

Solve each task through transformed views—rotations, reflections, color permutations, crops and object orderings—and combine independent scores.

Why it can work
Perspective diversity improves candidate discovery and estimates invariance; naturally complements pass@2.
Failure mode
Augmentation count can dominate runtime and correlated views can create false confidence.
[S28][S25]
ARC‑AGI‑2paper77/100

MDL / inference-time compression

Low-correlation portfolio bet

Optimize a compact per-puzzle model or program whose description length explains the visible pairs and predicts missing outputs.

Why it can work
No pretraining dependency and errors differ from LLM/DSL solvers; useful as a second-attempt source on selected tasks.
Failure mode
ARC-AGI-2 coverage is currently limited and per-task optimization can be expensive.
[S29]
ARC‑AGI‑2inference86/100

Object graph + relational search

Core representation

Convert grids into candidate object decompositions and search relations such as containment, alignment, correspondence, motion and counting.

Why it can work
Many ARC tasks are easier at the object/relation level than as raw pixels; supports DSL, ranking and synthetic generation.
Failure mode
There is no unique object decomposition. A single segmentation policy creates brittle blind spots; preserve multiple decompositions.
[S04]
ARC‑AGI‑2inference74/100

SAT/SMT/ILP constraint solving

Niche branch

Encode unknown mappings, object correspondences, symmetries or counts as constraints and solve exactly.

Why it can work
Excellent for permutation, matching and consistency-heavy families; produces proofs or clear infeasibility.
Failure mode
Poor fit for generative shape construction unless paired with a rich template library.
[S04]
ARC‑AGI‑2proposal72/100

Task embedding / meta-learned adapter generator

Moonshot

Infer a task vector from demonstrations and generate adapter weights, prompts or DSL priors without running many gradient steps.

Why it can work
Could deliver TTT-like adaptation with far lower per-task wall time.
Failure mode
Requires a broad synthetic meta-training distribution and can collapse to dataset-specific shortcuts.
[S26]
ARC‑AGI‑2community62/100

Large VLM natural-language solver

Use only as proposer

Render demonstrations as images and ask a VLM to explain the rule or emit code/candidate grids.

Why it can work
Can surface semantic hypotheses and unusual compositions that small specialized models miss.
Failure mode
Unverified direct grid output is exactness-hostile and a large model consumes multiple L4s; keep it outside the critical path or quantize heavily.
[S13][S12]
ARC‑AGI‑2recent71/100

Reflective multi-agent program synthesis

EvoMolior research method, not default runtime

Agents propose perceptions, latent programs, executions and critiques, with a meta-controller deciding which branch to pursue.

Why it can work
Good match for offline discovery and solver evolution; ARCANA is a current example of this direction.
Failure mode
The July 2026 paper is too recent for robust competition evidence, and runtime societies duplicate compute under a 12-hour cap.
[S30]
ARC‑AGI‑2baseline68/100

Brute-force geometric/color transforms

Mandatory cheap baseline

Enumerate identity, crop, palette mappings, flips, rotations, translations, tiling, overlays and simple component rules.

Why it can work
Solves easy tasks in milliseconds, creates reliable candidates and frees GPU time for hard tasks.
Failure mode
Limited compositional depth; naive enumeration produces redundant candidates.
[S04]
ARC‑AGI‑2inference87/100

Learned verifier / candidate ranker

Critical glue

Rank exactly fitting programs and neural outputs using leave-one-out reconstruction, equivariance, perturbation stability, MDL and cross-family consensus.

Why it can work
The core problem is not only generation: many hypotheses fit demonstrations. Better selection converts solver diversity into pass@2 gains.
Failure mode
A ranker trained on synthetic distributions may confidently prefer synthetic-style rules over hidden-task abstractions.
[S21][S28]

Portfolio logic

ARC‑AGI‑2 branches are valuable when their errors are different. ARC‑AGI‑3 branches are valuable when they reduce real environment actions or wall-clock. This is why model merging is lower priority for ARC‑2 and per-action multi-agent debate is lower priority for ARC‑3.

License policy

Prefer Apache-2.0 or MIT checkpoints and pin the exact repository revision. ARC Prize requires submitter-authored code/methods under a permissive public-domain-style license such as CC0 or MIT-0, while third-party components must at least permit public sharing. Keep a machine-readable bill of materials and preserve notices. [S02]

Model weights, tokenizer, custom kernels, datasets and code may carry different licenses. “Open weight” is not automatically “competition-compatible.”

Model admission test

  1. Cold-load succeeds offline twice.
  2. Peak VRAM leaves ≥15% safety margin.
  3. Structured action / exact grid format succeeds ≥99.5% after deterministic repair.
  4. ARC-specific holdout gain survives three seeds.
  5. Gain remains positive per wall-clock minute.
  6. License and redistribution path are documented.

Adapter design

ARC‑AGI‑3 adapters

P0 Train consequence prediction and legal action before “better reasoning.”

  • Targets: attention Q/K/V/O, MLP projections; separate experiment for multimodal projector.
  • Labels: changed components/cells, inventory delta, terminal/reset, action legality, predicted information gain.
  • Starting ranks: 16/32/64; DoRA as an equal-compute comparison, not an assumption. [S31][S35]
  • Losses: action CE + delta prediction + legality + calibrated confidence.
  • Preference stage: efficient successful trajectory > successful but wasteful > repeated no-op/illegal trajectory. [S34]

ARC‑AGI‑2 adapters

P0 Separate the global abstraction adapter from task-time adapters.

  • Global SFT on executable synthetic tasks with provenance and ambiguity scores.
  • Task-time QLoRA on geometric/color augmentations of only the visible demonstrations.
  • Hold out one pair or augmentation family for early stopping.
  • Retain multiple task adapters/seeds only when they add distinct candidates.
  • Do not merge adapters until marginal pass@2 has been measured.

What to preserve from the winner

Multimodality, raw ASCII/grid access, optional segmentation, a live Python workspace and rolling eviction. The official milestone analysis reports that better models and multimodality drove gains while more handcrafted tools could hurt. [S08]

Four runtime profiles to benchmark

A · Qwen3.6‑27B‑FP8 REPL

Best initial ceiling. Permit read-only Python over frame/grid/state objects, bounded NumPy operations and path/search helpers. The only environment mutation is submit_action(), which validates legality and executes exactly once.

Kill gate: if Python failures, latency and long outputs cause lower useful-actions/minute than direct Gemma on three clean game families.

B · Gemma 4 31B direct policy

Best operational control. One structured response with state-change summary, plan and one action; deterministic repair and salience fallback. Keep this implementation simple because the public profile with extra candidate/arbiter machinery performed best when those features were disabled. [S08]

Kill gate: retain even if it loses overall, provided it wins on enough game families to serve as a router branch or fallback.

C · Compact model router

Run GLM‑4.6V‑Flash or Phi‑4 Reasoning Vision on routine follow-through. Invoke Qwen only when novelty, contradiction, no known plan, unseen object signature or low confidence fires.

Kill gate: no reduction in wall-clock per completed level, or more than a small completion regression at matched action budget.

D · One-step model-predictive controller

Generate 2–4 candidate actions only at high-uncertainty states. A learned delta/value head ranks them; execute one. This is not deep tree search—hidden goals and model error make long imagined rollouts unreliable.

Kill gate: predicted-delta calibration below the simple empirical transition table, or candidate generation consumes more time than the action savings justify.

Context and memory policy

Working context

Start with 32K–64K plus external structured memory, then compare 128K. Qwen’s model card recommends large context for general thinking, but the ARC winner explicitly used eviction. The contest-specific optimum must be measured. [S12][S08]

Persistent memory

Keep hypotheses with support/contradiction counts, action signatures, object transitions, inventory/state variables, solved-level summaries and current plan. Never summarize away raw evidence for the most recent transitions.

Eviction

Evict raw turns after extracting immutable transitions. Preserve the system prompt, legal actions, last 3–8 transitions, stable hypotheses and unresolved contradictions. Summaries must cite transition IDs.

Why independent workers beat default tensor parallelism

A 4B model fits comfortably on one 24GB L4, while exact candidate execution and pass@2 selection are cheap on CPU. Four independent hypotheses create more value than pooling PCIe-connected memory for one generic model—unless a measured large-model branch proves otherwise. L4 specifications list PCIe Gen4 rather than a high-bandwidth scale-up interconnect. [S09][S22]

Branch A · Qwen3‑4B global specialization + task-time adaptation

Offline global checkpoint

  • Train on executable programs, not model-written answer grids.
  • Balance primitive, compositional and adversarial ambiguous families.
  • Use compact grid tokens and 2D/role embeddings.
  • Supervise rule/program sketches as auxiliary targets only when executable.
  • Publish base revision, tokenizer surgery, adapter and data generator hashes.

Per-task QLoRA

  • Generate spatial/color/object-order augmentations from visible pairs.
  • Reserve a leave-one-pair-out or augmentation-family validation slice.
  • Run several short schedules rather than one long overfit.
  • Rollback to the global checkpoint when validation consistency falls.
  • De-augment, deduplicate and score candidates exactly.

score(candidate c) =
    4.0 * exact_demo_fit(c)
  + 2.0 * leave_one_out(c)
  + 1.5 * equivariance(c)
  + 1.0 * perturbation_stability(c)

  - 1.0 * brittleness(c)

choose attempt_1 = argmax score(c)
choose attempt_2 = argmax [
    score(c)
  + lambda * family_diversity(c, attempt_1)
  + mu * prediction_distance(c, attempt_1)
  - nu * shared_failure_signature(c, attempt_1)
]

Weights are starting hypotheses for EvoMolior to tune on clean held-out tasks. Do not optimize them on the Kaggle public leaderboard alone.

Why model merging is usually the wrong ARC‑2 optimization

TIES and DARE are valuable general techniques for combining fine-tuned deltas, but ARC‑AGI‑2 scoring explicitly rewards a two-output portfolio. A merge that produces one “average” solver may reduce the error diversity that gives the second attempt value. Test merged models only against the stronger standard: does the merge increase unique pass@2 solves at equal compute? [S36][S37][S04]

12. Risk register and stop conditions

The fastest way to lose the competition is to mistake an attractive mechanism for a measured improvement. These risks should exist as executable tests in EvoMolior, not as final-report caveats.

Critical

Public-task overfitting

Signal: large gain on known games/tasks, collapse under palette/control/object mutations.

Control: blind procedural packs, provenance hashes, adversarial transformations.

Critical

Spurious ARC‑2 interpolation

Signal: exact demonstration fit, low leave-one-out and equivariance.

Control: rank generalization evidence above model confidence; preserve a diverse second attempt.

Critical

Hardware drift

Signal: model fits only a Blackwell-specific format or wheel.

Control: FP8/BF16 portable path, device introspection and a tested fallback engine.

High

Large context as false memory

Signal: tokens and latency grow while contradictions/repeated actions do not fall.

Control: transition IDs, structured causal ledger, raw-history eviction ablation.

High

Quantization damage

Signal: generic benchmarks stable but coordinates/colors/JSON regress.

Control: task-specific quantization suite and BF16/FP8 reference outputs.

High

Society overhead inside Kaggle

Signal: more agents produce more tokens but no unique solves or action savings.

Control: use EvoMolior offline; compile one lean runtime; require marginal coverage per compute.

High

Outer-loop confound

Signal: new architecture credited for gains actually caused by more refinement/augmentation.

Control: equal-parameter, equal-data, equal-FLOP baseline as urged by HRM analysis. [S25]

High

License incompatibility

Signal: model is downloadable but redistribution/derivative terms are unclear.

Control: pin revision, preserve notices, prefer Apache/MIT, block compiler on unresolved assets. [S02]

Medium

Model merge destroys diversity

Signal: pass@1 rises slightly, unique second-attempt solves fall.

Control: retain separate adapters/families unless merged pass@2 wins at equal compute.

Medium

World-model overconfidence

Signal: predicted deltas are calibrated on synthetic worlds but wrong on novel mechanics.

Control: uncertainty, empirical transition fallback and occasional exploration outside model preference.

Medium

Runtime starvation

Signal: a few ARC‑2 tasks consume most GPU-minutes.

Control: global and per-branch deadlines, dynamic queue, provisional output writes.

Medium

Leaderboard proxy failure

Signal: public score changes dominate research decisions despite noisy/small samples.

Control: internal blind family-stratified evaluation and only occasional Kaggle confirmation.

13. Final recommendation

Build one conservative system that can submit today, then spend research compute only on interventions that add blind, hardware-normalized value.

ARC‑AGI‑3 final target

Qwen3.6‑27B‑FP8 bounded REPL with raw image/grid/component views, strict legal-action gateway, transition-delta verification, hypothesis ledger, dead signatures and rolling eviction. Benchmark against a deliberately simple Gemma 4 31B direct policy. The highest-value next weight change is a consequence/legality adapter; the highest-value architecture bet is a one-step world-model head, but only after the baseline is stable. [S08][S12][S13]

ARC‑AGI‑2 final target

Four independent L4 workers: Qwen3‑4B global+task-time adaptation, 2D masked refinement, URM/TRM recurrence and executable DSL/Python synthesis. A CPU verifier/ranker chooses two outputs for marginal coverage. The highest-value new research branch is an equal-compute URM-style recurrent model plus better synthetic task identifiability—not a larger sharded LLM. [S09][S21][S22][S24]

EvoMolior final target

Operate as the durable model-development society: source ledger, hypothesis queue, dead-end memory, multi-fidelity experiments, skeptical blind grading, red-team mutations and submission compiler. The Kaggle notebook should be the compact compiled product of that society, not the society itself. [S38]
