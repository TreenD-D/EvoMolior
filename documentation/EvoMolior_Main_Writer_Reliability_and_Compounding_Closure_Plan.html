    EvoMolior Final-Output Closure Plan#

    Reliable Codex/Luna runs, a guaranteed main-writer artifact, and working compounding#

    Evidence cut2 August 2026
    Primary runGate-D ARC-AGI-2 v28-r3
    Backend constraintCodex / gpt-5.6-luna retained
    Architectural invariantCouncil → competitive groups + graders → check-in → repeat

    Executive decision: stop treating the final notebook as something that may be generated only after strict winner acceptance. The current order creates a circular dependency: strict acceptance needs a valid notebook, while the normal writer is withheld until accepted writer authority exists. Make the notebook a continuously maintained, provisional run artifact; run the main writer before final acceptance; then use deterministic validation to upgrade the artifact to accepted authority or publish it honestly as provisional.

    The most important conclusion is:

    EvoMolior successfully ran a 17.55-hour society and a complete evaluation institution, but it never materialized the primary artifact that the institution was supposed to improve.

    That is an orchestration and artifact-contract defect, not evidence that more agent roles, stronger grading, or another full provider retry is needed.

    2. Evidence-derived diagnosis#

    2.1 The writer–acceptance cycle is deadlocked#

    The observed sequence is effectively:

    worker rounds
  → strict mandatory tests evaluate missing/incomplete final artifact
  → every group receives 0/6 and mandatoryFailure=true
  → no accepted winner/writer authority
  → normal final writer is not spawned
  → no notebook exists to pass the mandatory tests
  → recovery tries to generate the whole notebook from scratch
  → timeout or contract rejection

    The v28-r3 comparative fix resolved a leader every round, including a final-round comparative candidate, but normal writer spawning remained zero because accepted authority was withheld. That proves comparative source selection and accepted publication are still coupled at the wrong point. [E1][E2]

    Required inversion:

    comparative source selection
  → provisional main-writer candidate
  → concrete notebook compilation
  → structural/execution/benchmark validation
  → strict accepted-authority resolution
  → accepted or provisional publication

    The writer is a candidate producer. Passing the gates upgrades its authority; the gates must not be prerequisites for invoking it.

    2.2 The primary deliverable contract does not describe the primary deliverable#

    The archived DeliverableBlueprint says:

    • the receiver intends to use a staged submission.ipynb;
    • primaryFormat is JSON;
    • companion format is Markdown;
    • all 13 component specifications have empty sourceNodeIds;
    • no first-class notebook artifact is declared. [E4][E6]

    This is a direct semantic mismatch. The decision package can describe a notebook but cannot require, track, validate, or archive one as the primary output.

    The current generic package is therefore capable of becoming structurally complete while the actual requested artifact is absent. The run reported recovery component coverage of 7/8, yet the package mostly contains authority placeholders and no notebook. That metric measures file/component presence, not receiver value.

    2.3 Interim snapshots are present but not usable#

    The run reports 18/18 interim snapshot coverage. However, the recovery source set contains only:

    • three group IDs;
    • three snapshot hashes;
    • no public evidence references;
    • no candidate notebook path;
    • no benchmark report;
    • no artifact module references. [E4][E6]

    Consequently the provisional compiler can render only statements such as “no accepted winner exists.” It cannot recover the best notebook, code module, experiment, or benchmark progress from earlier rounds.

    Current metric failure: interim_snapshot_coverage=1.0 is true syntactically and false semantically.

    Derived from the 48 ordinary-exit references in run-metrics-v1.json:

    This does not mean Critics are bad; it means the system built an excellent review institution around too little artifact production. Seven Archivists per group are especially expensive for a run whose primary output never existed.

    2.5 The evaluation institution is overproducing relative to the delivery institution#

    The run produced:

    • 54/54 valid grader bundles;
    • 18 criteria freezes;
    • 204 unique grader requirements;
    • calibration 18/18;
    • score replay error 0;
    • only 2/11 mandatory-node coverage;
    • no notebook. [E4][E6]

    There were roughly 18.5 unique grader requirements per mandatory node, or 102 requirements per covered mandatory node. This is not evidence that grading caused the failure, but it is strong evidence that the current budget distribution is inverted: evaluator sophistication is no longer the marginal bottleneck.

    2.6 Compounding mechanisms activate but do not feed later work#

    Mechanism Observed Missing link
    Outlier acceptance 4/6 0/4 downstream adoption
    Tool transport 4 attempts, 2 failures 50% transport failure rate
    Tool repair 1 typed diagnostic emitted 0/1 diagnostic consumption
    Competitive capture Activated No downstream resource use
    Instrumental reward None spent reward_usefulness not applicable
    Tool reuse No promoted tool No later execution or simulation influence

    The architecture is recording potential compounding objects, but the scheduler does not convert them into compulsory next-round work. Accepted Outlier proposals and typed repair diagnostics can simply die in the substrate.

    2.7 The recovery writer is solving the wrong problem at the wrong time#

    Recovery attempt 2 failed for:

    • blank/missing cell IDs;
    • missing challenge_data;
    • missing prior_data;
    • missing counterfactual.baseline;
    • missing sample_submission;
    • missing one-result-row-per-test-input evidence. [E1][E2]

    These are mostly deterministic serialization, symbol, metadata, and execution-contract obligations. They should not depend on a model remembering every requirement in a one-shot recovery call. The host should generate notebook structure and IDs, inject immutable metadata, and run typed validation. Luna should write and repair solver semantics, not manually serialize nbformat.

    3. Non-negotiable target architecture#

    Retain the project loop:

    INPUT
  → GENESIS COUNCIL
  → COMPETITIVE WORK / DELIVERY GROUPS
      + PARALLEL COMPETITIVE GRADER GROUPS
  → SEALED ROUND CHECK-IN AND EVALUATION
  → CAPTURE / DISCLOSURE / REPAIR / RESOURCE UPDATE
  → NEXT ROUND
  → MAIN WRITER + VALIDATION
  → ACCEPTED OR PROVISIONAL PUBLICATION

    Add a persistent artifact spine through the entire loop:

                             ┌──────────────────────────────────────┐
                         │ Persistent Primary Artifact Spine   │
                         │ scaffold → patches → snapshots      │
                         │ → benchmarks → best-so-far → final  │
                         └──────────────────────────────────────┘
                                      ▲              │
Input → Council → Groups + Graders → Check-in ───────┘
                                      │
                                      └→ next-round repair / experiment tasks

    Core invariant#

    After admission and primary-artifact scaffold creation, a terminal post-runtime outcome may not lack a primary artifact reference.

    Strict acceptance may be withheld. The notebook may be provisional and may fail to improve the baseline. But a healthy admitted run must not finish with only an administrative package.

    9. Make the writer incremental and timeout-resilient on Codex/Luna#

    9.1 Do not generate the notebook in one call#

    Use bounded, persistent steps:

    1. inspect source bundle and existing workspace;
    2. author/repair grid and object primitives;
    3. author/repair candidate families;
    4. author/repair ranking and LOO evaluator;
    5. author/repair receiver generation;
    6. run local validation and write a typed failure report;
    7. repair only failed modules;
    8. compile the notebook host-side.

    Every step writes files and writer-progress.json before the Codex process exits.

    9.2 Persist partial work on timeout#

    The first recovery attempt timed out and no valid deliverable was recorded. Change timeout handling:

    • never delete the writer workspace on timeout;
    • hash all modified files;
    • run host validators on the partial workspace;
    • if it improves the best valid snapshot, preserve it;
    • issue a narrow continuation task against the exact failures;
    • if no continuation succeeds, publish the last valid snapshot.

    9.4 Protected writer budget#

    Reserve at run admission:

    • one main integration call;
    • at least two repair calls;
    • deterministic compiler/validator compute;
    • final archive compute.

    Worker and grader allocation cannot consume this reserve. Provider-wide capacity cannot be guaranteed, but the artifact spine means late provider unavailability still publishes the last valid notebook.

    9.5 Codex execution mode#

    Retain exact codex-chatgpt:gpt-5.6-luna, with no fallback. Use:

    • file-editing/code mode for Builders and main writer;
    • structured JSON only for small plans, patch manifests, and diagnostics;
    • medium reasoning for routine Researcher/Critic/Grader work;
    • high reasoning selectively for main integration and difficult semantic repair;
    • session-independent calls with durable workspace state, so a model-refresh/session loss does not erase work.

    10. Reclassify gates by phase#

    The current six mandatory tests appear to behave as final-output tests during all rounds. That is acceptable for acceptance reporting but not as the only progress authority.

    @Serializable
enum class GatePhase {
    ROUND_PROGRESS,
    PRE_WRITER,
    POST_WRITER_STRUCTURE,
    POST_WRITER_EXECUTION,
    ACCEPTANCE_BENCHMARK,
    PUBLICATION_INTEGRITY,
}

    10.1 Round-progress gates#

    Examples:

    • workspace exists;
    • a fresh candidate differs from the supplied baseline;
    • required source modules compile;
    • at least one real solver family exists;
    • partial LOO report has exact provenance;
    • repair diagnostic was consumed.

    They guide scheduling and comparison. They do not create accepted publication.

    10.2 Post-writer gates#

    Examples:

    • notebook structure and cell IDs;
    • required functions/signals;
    • self-tests;
    • exact receiver schema and row count;
    • full local challenge execution.

    These run after the main writer has materialized the candidate.

    10.3 Acceptance gates#

    Examples:

    • complete 358-row benchmark;
    • repeated byte-identical report;
    • improvement over v18 baseline;
    • no held-out leakage;
    • exact lineage and final manifest.

    These determine accepted status, never writer invocation.

    10.4 Gate liveness compiler#

    At Council compilation, calculate:

    earliest producer round
→ earliest artifact compilation round
→ earliest validator round
→ earliest gate evaluation round

    Reject any test whose scheduled evaluation precedes its producer. This prevents a final-output gate from permanently starving its own writer.

    11. Rewrite the round loop around artifact progress#

    Round 0 — establish viable artifacts#

    For every group:

    1. instantiate deterministic notebook scaffold;
    2. spawn ArtifactOwner Builder first;
    3. spawn one Researcher/algorithm specialist;
    4. optionally spawn one Outlier;
    5. compile and validate candidate at round end;
    6. persist an artifact snapshot even when benchmark is zero.

    Round-0 exit condition: every group has a fresh notebook candidate or an explicit artifact-rescue record.

    Rounds 1–2 — repair and broaden#

    • consume structural/semantic diagnostics before new optional work;
    • schedule accepted Outlier proposals as concrete experiment tasks;
    • add distinct solver families;
    • execute the 358-row benchmark;
    • preserve best-so-far snapshots.

    Rounds 3–4 — adversarial validation and integration#

    • red-team candidate failure signatures;
    • compare branches using real LOO metrics;
    • use resource yields for Builder continuation and validation compute;
    • integrate only changes that improve or expand pass@2 coverage.

    Round 5 — final candidate preparation#

    • no new broad exploration unless the artifact is already valid;
    • compile the final source set;
    • run main writer/integrator;
    • run post-writer validators;
    • resolve accepted/provisional status;
    • archive both final and best historical candidate if different.

    Artifact-rescue mode#

    Trigger when a group has no structurally valid candidate after a productive round:

    suspend optional Archivist, Outlier, PerspectiveTaker, and duplicate Critic calls
reserve Builder + validator budget
clone deterministic scaffold + best public modules
run bounded writer repair
compile notebook

    If rescue still cannot improve the candidate, retain the scaffold, mark the group provisional, and stop spending later rounds pretending output progress exists.

    12. Fix role allocation and competition design#

    12.1 Productive-role floor#

    For an artifact-required group, per round:

    1 mandatory ArtifactOwner Builder
1 Builder or Researcher for the highest-priority open/repair node
0–1 Critic after a candidate exists
0–1 Outlier in exploration rounds
0 ordinary Archivist by default

    The selector may add roles, but it cannot remove the artifact owner while the primary artifact is below BENCHMARKED.

    12.2 Summary plane#

    Move round summarization out of ordinary worker competition:

    • deterministic event-to-summary compiler;
    • optional Summary agent only for compression/receiver language;
    • no worker node, capture, or productive-role slot;
    • separate Summary fitness.

    12.3 Structured overlap instead of zero overlap#

    The observed portfolio overlap was 0.0. Complete disjointness supports diversity but can prevent any group from constructing a complete candidate.

    For ARC use:

    Replicated backbone in every group

    • valid notebook scaffold;
    • required API and receiver contract;
    • LOO harness;
    • final integration node.

    Divergent branches

    • object/connected-component DSL;
    • geometric/palette programs;
    • relation/topology programs;
    • refinement/mutation family;
    • MDL/object-perspective family.

    Recommended design target: a common artifact backbone plus disjoint solver families, not 0% or 100% semantic overlap.

    12.4 Comparative score uses artifact facts#

    Grader broad scores remain useful, but candidate selection should prioritize:

    1. structural validity;
    2. execution validity;
    3. 358-row top-1 / any-two;
    4. runtime and fallback rate;
    5. marginal diversity of second attempt;
    6. comparative grader score.

    A group with beautiful prose and no notebook cannot outrank a group with a valid executable candidate.

  → outcome ADOPTED / REJECTED / DEFERRED_WITH_REASON

    Acceptance without downstream disposition is not compounding.

    13.4 Capture rewards must be spendable#

    Current capture activated with no downstream use and no instrumental reward spending.

    Translate captured yield into exact actions:

    • one additional Builder patch budget;
    • one benchmark execution budget;
    • one independent validator call;
    • one repair continuation.

    Persist rewardSpendPurpose and later score/artifact delta. If no permitted action can consume a yield, do not report the capture as useful compounding.

    13.5 Tool infrastructure versus agent-authored tools#

    The independent notebook validator and 358-row benchmark are runtime-owned task tools. They must always be available and must not depend on an agent-authored tool reaching promotion.

    Keep arc_candidate_portfolio_audit as an agent-authored compounding opportunity, but separate it from minimum receiver validation:

    SYSTEM VALIDATOR
  validates every candidate notebook
  cannot be blocked by tool promotion

AGENT-AUTHORED AUDIT TOOL
  may add reusable analysis and later-agent value
  earns tool/reuse fitness only after promotion and use

    This prevents tool-compounding failure from eliminating the primary output.

    13.6 Archive archaeology integration#

    For the immediate ARC profile, import the supplied v14 notebook and v18 reports as provenance-bound heritage candidates:

    • immutable source hashes;
    • NON_ACCEPTED_HISTORICAL status;
    • candidate code may be forked into group workspaces;
    • old scores do not transfer;
    • every current candidate must rerun current validators and benchmark;
    • the fresh output must have a new artifact hash and explicit lineage.

    Do not implement unrestricted cross-run archaeology before the writer spine is stable. Add the heritage reference contract now so broader archive archaeology can plug in later without bypassing current-run authority.

    23. Definition of done#

    Runtime/output reliability#

    • admitted run creates a fresh primary notebook scaffold before ordinary worker execution;
    • each group maintains a persistent artifact workspace;
    • every sealed round exports an artifact-bearing snapshot;
    • main writer is invoked for accepted and provisional source authority;
    • writer timeout cannot erase the last valid candidate;
    • a completed post-runtime run always includes submission.ipynb;
    • strict gate failure alone does not produce process exit 1;
    • manifest verifies accepted/provisional separation.

    Main writer#

    • final_deliverable_spawn or renamed main_writer_spawn occurs at least once;
    • writer source set is persisted and non-null;
    • Luna edits source files in a durable workspace;
    • host compiler owns nbformat, IDs, metadata, and serialization;
    • typed repair closes missing symbol/signal violations;
    • final artifact hash and writer lineage are durable.

    Artifact value#

    • notebook passes structural validation;
    • every code cell compiles;
    • required API functions and receiver signals exist;
    • full local challenge execution emits the exact schema and row count;
    • 358-row benchmark executes and is persisted;
    • v18 comparison is explicit;
    • repeated report is required before an improvement claim.

    Compounding#

    • best-so-far artifact survives later regressions;
    • accepted Outlier proposals receive explicit downstream disposition;
    • typed repair diagnostics are consumed or explicitly deferred;
    • capture rewards fund actual next-round work;
    • artifact changes preserve node/agent/diagnostic lineage;
    • no ordinary Archivist flood starves Builders and Researchers.

    Authority#

    • comparative ranking and score replay remain exact;
    • mandatory gates remain strict;
    • accepted winner/writer authority is created only after artifact validation;
    • provisional artifact is never mislabeled accepted;
    • no Kaggle, hidden-label, or official-score claim is made without evidence.
