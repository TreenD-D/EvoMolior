Qwen Cloud · Agent Society · Technical Deep Dive

Authority before autonomy.

EvoMolior is a multi-agent runtime in which short-lived specialists work inside competing societies, while durable knowledge, exact task authority, independent grading, and publication evidence survive individual agents.

The agent is disposable. The reviewed substrate is not.
Two authority worlds Workers receive redacted task views. Graders receive separate sealed criteria and exact evidence bundles.
Three execution boundaries Ordinary agents run in-process, promoted tool executables run in bounded child processes, and blind scoring runs in a separate child JVM.
One publication gate Output contracts, sealed tests, quiescence, cost settlement, lineage, metrics, replay, and manifests converge before release.

System overview

One system, four useful zoom levels.

The easiest way to understand EvoMolior is to move from the full run, to a worker society, to one agent, and finally to the durable authority and evidence that outlive every model invocation.

System Objective to receiver How interfaces, Council compilation, societies, graders, and publication compose into one run. Group One competing society How a group gets a redacted Atlas view, isolated substrate, role allocation, critique, and round feedback. Agent One mortal specialist How a node lease becomes context, governed actions, staged evidence, a Death Note, and post-round Critic review. Evidence One publishable result How exact grades, capture, sealed tests, lineage, metrics, replay, and manifests gate release.
Principal runtime authority: EvoMoliorRunService owns admission, run state, round orchestration, worker and grader coordination, Atlas mutation boundaries, finalization, and archival. The system is distributed by responsibility, but not by ambiguous ownership.
1

Entry + model plane

Interfaces create a run envelope; the selected backend supplies model execution.

Users enter through the CLI, authenticated remote dashboard, or desktop control panel. These surfaces converge on the same service-level run model: objective, source pack, constraints, model assignments, budgets, and output contract. This submission route selects Qwen Cloud; reusable runtime composition also supports OpenRouter and local Codex/ChatGPT execution.

Interface paths

CLI: starts normal runs, benchmarks, self-improvement, and the remote dashboard.

Ktor dashboard: authenticates operators, supervises CLI runs, and exposes bounded run state and artifacts.

Desktop: composes the real service in-process for local control and inspection.

IPC: an implemented Ktor/WebSocket alternative, not the default desktop path.

Qwen Cloud paths

Text agents: the QWEN_CLOUD backend resolves supported model IDs and uses a DashScope-compatible chat-completions client.

Tools and structure: the adapter preserves raw tool-call JSON, supports required tool choice, and disables provider thinking where tool or structured-output contracts require it.

Images: final visual assets use a separate direct DashScope image-generation service and local validation path.

2

Compiled authority

The Genesis Council turns intent into executable, sealed authority.

EvoMolior does not activate a society directly from a prompt. An eight-role Council builds a typed StartingField, and deterministic compilers reject incomplete or contradictory authority before workers or graders can start.

1 · Task anatomy

Task Anatomist decomposes the objective into typed nodes, dependencies, proof contracts, and executable validation intent.

2 · Specialist closure

Six dependent specialist roles work in parallel and receive only their role-owned repair errors.

3 · Synthesis

The final Council role combines validated specialist outputs into one candidate authority bundle.

4 · Pure compilation

StartingField and sealed-test compilers validate exact predicates and construct deterministic runtime contracts.

5 · Shared seal

Worker field, grader field, Atlases, tests, and receiver contract become hash-bound before activation.

Worker Node Atlas

Typed tasks, dependencies, evidence and capture policies, and lineage rules; separate execution-state projections carry leases, disclosure, evidence, capture, and yield outcomes.

Competitive Grader Atlas

A sealed evaluation frontier mapping receiver obligations and worker nodes; per-round criteria freezes and score bundles are appended later through grader authority.

sealed-tests-v3

Typed general tests compiled before activation, evaluated contextually, and reused at final publication.

StartingField seal

A shared cryptographic commitment binding worker and grader authority so drift can be detected.

Fail-closed startup: missing Council configuration, Council timeout, malformed role output, unresolved closure errors, compiler rejection, or a bad seal stops the run before society activation. Test-mode defaults intentionally bypass this path and are not equivalent to a sealed production StartingField.
3

Worker-group layer

A society is an isolated substrate plus a changing population of roles.

Each competing group receives a group-specific, stage-redacted projection of the sealed worker Atlas. It owns a separate database, local work queue, agents, messages, tools, trust state, dead ends, and round history.

What is isolated per group

Room / SQLite KB + KG Staging WiP tasks Messages Tools Trust Dead ends Legacy protocols

Group-local canonical state is separate even though global competition authority is shared.

What a worker can see

A worker receives an AgentBootContext containing a redacted WorkerView, exact node lease, role, TTL, model assignment, budget, allowed tools, and bounded run context.

It does not receive the private Grader Atlas or unrestricted competitor state.

One round

Reset

Competition state advances and delayed dispatches become eligible.

Allocate

Atlas snapshots and node demand drive role portfolios and exact leases.

Spawn

Each LifecycleManager creates local jobs or selects the optional VM branch.

Critique

Staged work is promoted, rejected, or arbitrated; trust and organization update.

Mutate

Grades drive capture, disclosure, yields, fitness, outlier handling, and the next round.

A group’s live remaining budget is telemetry from currently active agents, not the next-round spending ceiling. New spawning uses the configured per-generation ceiling plus explicit earned credits.
4

Single-agent layer

One agent is a leased capability, not an owner of truth.

An ordinary node-assigned worker is created for a role and exact node portfolio; Outliers and special-purpose workers use dedicated authority scopes instead. The worker receives bounded context and tools, spends from a local budget ledger, stages evidence, and exits. It cannot directly promote canonical KB, KG, or tool state.

1Claim — ordinary workersAccept an exact Atlas node lease and WiP task.
2BootReceive role, TTL, budget, redacted WorkerView, and model assignment.
3Assemble contextRead selected KB/KG entries, run artifacts, messages, and node evidence.
4ReasonInvoke Qwen or the selected backend with structured output and role prompt.
5ActUse role-gated tools through constitutional and source-access policy.
6StageSubmit documents, KG proposals, constraints, tools, simulations, or deliverable components.
7ExitWrite a Death Note, or let the runner persist an emergency fallback on failure.
8Post-round reviewCritic authority promotes, rejects, or arbitrates staged contributions after worker termination.

Read surface

  • Index-first KB listing and semantic search; full entries only by selected IDs or explicit opt-in.
  • KG query, traversal, consistency checks, run artifacts, and approved messages.
  • Exact task authority from the redacted WorkerView and current lease.

Mutation surface

  • Staged documents and deliverable components.
  • KG facts and constraints awaiting Critic authority.
  • Source-access requests, tool execution, messages, contribution commits, and one-level subagent delegation.
Why mortality matters: the agent’s prompt context is not the system’s memory. Reviewed state is preserved in the group substrate; rejected work, dead ends, tool results, messages, and Death Notes remain inspectable after the agent exits.
Delegation is bounded to one subagent level. EvoMolior does not recursively create unbounded societies. On local desktop/runtime paths, ordinary agents run in-process; agent mortality is a lifecycle and authority boundary, not automatically an OS-process boundary.
5

Grader + competition layer

Criteria are frozen before evidence is revealed.

Grader societies are not ordinary worker roles with a different prompt. They have separate local databases, private authority, exact bundles, and a dedicated judging and scoring path. GraderRunner can enforce sealed role-to-model assignments when runtime composition supplies that authority.

1 · Methodology

GraderResearcher, GraderBuilder, and GraderCritic develop and review criteria during the worker round.

2 · Freeze

Criteria become canonical before worker evidence is revealed for judging.

3 · Exact bundles

RoundJudge evaluates assigned Atlas nodes using exact grader and node-evidence bundles.

4 · Blind scoring

A separate child JVM runs the submission gate, scoring engine, quorum, and MetaJudge arbitration.

5 · State mutation

Capture, yields, rewards, fitness, disclosure, and feedback commit atomically at the round boundary.

Exact evidence, not artifact volume

Node-specific proof contracts determine what counts. Documents, KG facts, tools, simulations, and final components carry exact lineage into grading.

Finishing first, producing more text, or creating more artifacts does not by itself establish territorial ownership.

Disagreement is retained

Grader scores are aggregated under quorum rules. MetaJudge authority arbitrates qualifying disagreement, and deterministic score replay exposes the result path.

Unavailable or inapplicable observations remain explicit rather than being fabricated.

The scoring worker is isolated in a child JVM and authenticated with a per-run bearer token over loopback. That is a local process boundary, not a remote security perimeter. Legacy/fallback scoring paths still exist when full grader runners are not configured; two-phase grader claims apply to configured production runs.
6

Durable substrate layer

Persistence is partitioned by authority.

EvoMolior uses Room/SQLite stores with distinct responsibilities. Worker groups do not share one mutable database, graders do not grade from worker-local state, and Atlas mutations pass through serialized transactional authority.

Worker group store runs/<run>/groups/<group>/substrate.db

KB, KG, staging, WiP, messages, tools, trust, dead ends, events, Legacy, and group-local execution evidence.

Grader group store runs/<run>/graders/<grader>/substrate.db

Private criteria development, grader tools, exact snapshots, local staging, and sealed judging state.

Global Atlas store runs/<run>/control/atlas/substrate.db

Versioned Atlas authority, commits, projections, leases, evidence, capture, yields, disclosure, and state events.

Meta archive runs/<run>/groups/__meta_archive__/substrate.db

Winning snapshots, dead ends, Legacy, completion records, and continuation-facing durable run knowledge.

Cost ledger runs/<run>/groups/__cost_ledger__/substrate.db

Reservations, settlements, attribution, and publication checks that prevent unsettled cost state from looking complete.

Result bundle runs/<run>/results/outputs + runs/<run>/results/results.zip

Receiver files, typed metrics, replay material, manifests, and public-safe completion artifacts.

Room builders currently permit destructive fallback when a migration path is unavailable. Per-run stores are treated as reproducible run artifacts, not as a zero-data-loss, indefinitely migrated production database. Long-lived hosted retention needs an explicit migration policy before it should be treated as archival-grade storage.
7

Safety + isolation layer

Different risks have different boundaries.

EvoMolior combines typed application controls with process boundaries and an optional VM branch. The architecture names these honestly instead of calling every boundary a sandbox.

Application boundary Constitutional gates

Typed pre-side-effect checks cover staging, source requests, messages, tools, KG actions, and TTL-sensitive operations.

Network policy Approved source egress

Run allowlists, role-aware narrowing, explicit approval, redirect control, sanitization, and audited request/fetch tools govern external sources.

Child process ToolSubSandbox

Generated tools execute with bounded wall time and output. The default limits are 30 seconds, 50 KB stdout, and a 1 KB stderr tail.

Child JVM Blind scorer

Scoring runs in a separate authenticated loopback process over immutable requests, distinct from the desktop IPC service.

In-process lifecycle Ordinary agents

Normal CLI, benchmark, self-improvement, and desktop paths execute role agents in-process with authority and side-effect interception.

Optional VM branch Shuru

MicroVM execution exists as an alternate lifecycle branch when no local runner is selected; it is not the default production path.

What this does not prove: normal agents are not universally microVM isolated; the child-process tool runner does not itself demonstrate OS-level network isolation; source policy is an application-layer control rather than a blanket host firewall. Qwen image downloads use a separate HTTP path outside the agent SourceAccessPolicy fetch route.
8

Evidence + publication layer

Final writing is inside the validation boundary.

EvoMolior does not treat final synthesis as a trusted epilogue. The writer produces a candidate inside a bounded retry loop, and the same output contract and sealed tests decide whether publication may continue.

1 · Select evidence

Accepted components, contribution lineage, grades, and deliverable skeleton state form the synthesis input.

2 · Write candidates

The winner-side Builder emits the contract-specified file. Separately, FinalSynthesiser emits DST-derived Markdown, plaintext, or JSON artifacts for each group.

3 · Validate in retry

Shape, required components, image assets, lineage, and sealed tests run before the retry budget is exhausted.

4 · Settle run

Publication waits for quiescence, no active workers, settled cost reservations, and coherent causal lineage.

5 · Archive

Receiver artifact, typed metrics, score replay, manifest, round summaries, and result ZIP become inspectable outputs.

Receiver artifact

The human- or machine-consumable final deliverable defined by the compiled receiver contract.

Typed metrics

Section 18.2 observations with explicit AVAILABLE, UNAVAILABLE, and NOT_APPLICABLE states.

Score replay

Deterministic evidence for how grader inputs, quorum, arbitration, and score calculations produced the result.

Hash-linked manifest

Declared archive entries, sizes, hashes, and publication ordering for local integrity verification.

Publication validation proves contract shape, required evidence, lineage, and sealed-test behavior. It does not guarantee factual truth. Archive integrity is based on local hashes and persisted authority; it is not an external notarization service.

Failure semantics

Failure is data, not a cosmetic status.

Important boundaries either reject the action, stop activation, keep the value explicitly unavailable, or prevent publication. The system avoids converting missing authority into a successful-looking default.

FailureSystem responseEvidence retained
Council or compiler rejectionNo worker/grader activation.Role errors, compile errors, failure state, and startup diagnostics.
Invalid lease or role actionReject the action before side effect.Constitutional event and bounded error returned to the caller.
Unapproved sourceDeny fetch until authority grants access.Request, decision, role, host, and source-policy event.
Tool timeout / output overflowTerminate or truncate within configured bounds.Execution status, bounded stdout/stderr evidence, and tool version.
Grader quorum or bundle failureFail closed or mark the exact observation unavailable.Raw grader bundles, resolver result, and telemetry.
Invalid final candidateRetry within the writer budget; do not publish after exhaustion.Validation failures and publication state transitions.
Unsettled cost or active workBlock publication.Reservations, active authority, and quiescence diagnostics.
Unavailable metricEmit UNAVAILABLE, never a fabricated zero.Typed state and reason.

Glossary

The terms that carry architectural authority.

Compiled Council result
A StartingFieldCompileResult.Valid containing paired worker and grader StartingFields, ReceiverContract, NodeAtlas, GraderAtlas, sealed tests, consistency report, and shared seal.
Worker Node Atlas
The typed task graph plus evidence, capture, and lineage policy; separate execution-state projections carry leases, disclosure, evidence, capture, and yield outcomes.
Competitive Grader Atlas
A sealed evaluation frontier over mapped worker nodes and receiver obligations; it is distinct from later criteria freezes, score bundles, and MetaJudge execution.
WorkerView
A redacted projection of Atlas authority suitable for one ordinary worker and its leased nodes.
Contribution commit
A typed record connecting an agent’s staged work to node authority, evidence, and later publication lineage.
Critic pipeline
The canonical promotion boundary for documents, KG changes, tools, simulations, and components.
Capture
Deterministic node ownership/state derived from exact grades, not from completion order or artifact count.
Progressive disclosure
Evidence-gated release of later task stages to each group based on authoritative mandatory-node completion.
Death Note
A structured end-of-life record that preserves useful insight when an agent exits.
Receiver artifact
The final deliverable emitted only after output, evidence, settlement, replay, and publication gates pass.
What EvoMolior means by “agent society”
A society is not merely several model calls in one prompt. It has role allocation, separate identities, local persistent state, task leases, communication, critique, competition, independent grading, mortality, inherited reviewed knowledge, and explicit rules for disagreement and publication.
What “durable intelligence” means here
Durability refers to reviewed KB/KG state, staging history, tools, evidence, scores, capture, dead ends, Death Notes, metrics, replay, and archive artifacts. It does not mean that a model instance has hidden long-term memory or that learning automatically crosses every unrelated run.
What is intentionally not claimed
Universal microVM isolation, factual correctness guaranteed by validation, broad superiority over strong single agents, lower cost, fully independent graders using the same provider family, or externally notarized archives.
